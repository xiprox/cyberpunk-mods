# Vehicle Customizer

A planned customizer for Cyberpunk 2077's cars and bikes on NightCoop; [README.md](README.md) says what it's for and where things are.
`RECORD.md` holds what we found and decided, newest entry first; add an entry when a finding or decision changes how the mod works, and keep its "Installed" and "Not yet checked in the game" lines current.

- Say what went untested in the game. A probe shows what the files say, not what the game draws, so don't call something working until the user has seen it.
- Read the logs first for anything in-game: the engine's notes (`[VehicleCustomizer]` lines in the game's `r6/logs/redscript_rCURRENT.log`, and copied into each run's report), a run's folder in `dev/runs/`, and `C:\Users\wayne\Documents\CP77 Collected Logs\<player>\game\red4ext\plugins\NightCoop\nightcoop.log`. The old test's `test.log` and `live-copies.txt` are in `test/removed-from-game/`. `xip` is the user, `Bobson` is Bossun (clock 7 h behind), `Bleack` (clock 1 h ahead).
- Call NightCoop's SDK only from `VCCoop.OnFrame` (its `ListenFrame` callback) and `OnCoopEvent`, both on the game thread: from a DelaySystem callback or the screen it's refused as -2 (RECORD.md, 2026-11-07). Elsewhere read the engine's cached values and queue writes (`PutState`).
- Look game APIs up before using them, in `<game>\tools\redmod\scripts` and Codeware's `Scripts\Codeware.Global.reds`. Don't pass a `script_ref` parameter straight to a Codeware native: that crashed all three players in NightCoop Voice 0.3.0.
- While the game runs, never install, and never close it without being asked. While the user is testing, edit code only and wait for "install and restart".
- Running the game unattended (`tools/run-autotest.ps1`) needs the user's permission for that day; they gave it on 2026-11-06 and again just after midnight on 2026-11-07. Each run installs `dev/` and `mod/`, so don't run one while the user plays. Read the run's report and pictures in `dev/runs/` before saying anything works, and say what only the user's eyes can judge. Every run adds its times (loading, job, total) to `dev/runs/durations.csv`; look there for how long a job usually takes.
- After changing generated data, rerun `catalog/make-catalogs.py` and then `catalog/make-twins.py`; don't edit their outputs by hand.
- Parse Lua with `luajit -bl <file>` after changing it, since only the game runs it.
- Check redscript with `powershell -File ../../tools/check-scripts.ps1 -Mod vehicle-customizer`: it compiles the test's scripts beside every installed mod into the temp folder, on a hidden desktop, so it's safe while the game runs. Install redscript only with the game closed; it takes a restart.
- Run Python that reads game files with `-I`.
- WolvenKit 9.1.0 is at `H:\WolvenKit` (`WolvenKit.exe`), its command line at `H:\WolvenKit\Console\WolvenKit.CLI.exe`: `unbundle <archive> -o <dir> -w <pattern>` extracts a file by name, `convert serialize <file> -o <existing dir>` turns it into JSON and `convert deserialize` back, and `pack <folder> -o <dir>` makes `<folder>.archive` from the depot paths inside it. Packing warns that Oodle couldn't load and uses Kraken.dll; the game reads the result (the test's patches worked, and `rdar.py` reads them with the game's own Oodle). Reading the Yaiba showroom's layout it skipped one widget's script controller ("Can't read data for inkCanvasWidget.logicController"), so check a round trip before editing a layout that way.
- `experiments/areas/game-files/data/` is regenerated by `run-all.ps1`, so it stays out of git.
